# Чат ба асуулт — мобайл клиентэд засах зүйлс

2026-09-11. Сервер тал засагдаж `mncardio.itsystem.mn` дээр байрласан.
Доорх нь **Flutter клиент** талд үлдсэн алдаанууд — клиентийн код таных тул бид хөндөөгүй.
Мөрийн дугаар нь GitHub `main` дээрх `mobile/app/lib/...` (`165ce3c`)-д хамаарна.

## 0. Серверт юу засагдсан

- **Асуулт илгээх, тэмдэглэл хадгалах 500 өгдөг байсан — хоёр шалтгаантай.**
  1. `rec_status: 'A'` нь `int NOT NULL` багана руу бичигдэж байсан. Зөв утга нь **`9`**
     (9 = идэвхтэй, 2 = устгасан).
  2. Үүнийг засахад дараагийн алдаа гарсан: хуучин үеийн хүснэгтэд `id`, `id_group`, `user_mod`,
     `date_modif` заавал байх ба анхдагч утгагүй (`Cannot insert the value NULL into column
     'id'`). Эдгээрийг `ModelHelper` бөглөдөг тул бичилтийг `Models.X.create`-ээс
     `BaseControllerHelper.BaseCreate` руу шилжүүлсэн.

  Тиймээс зөвхөн `'A'`-г солих нь хангалтгүй. **`backend/api/patient/controller.js`-ийн локал
  өөрчлөлтөө pull хийхээсээ өмнө буцаа** — эс бөгөөс зөрчил үүснэ.
- **Үйлчлүүлэгч эмчтэйгээ чатлаж чадахгүй байсан.** Зөвхөн эмчийн баг (`DoctorsTeamPatient`)
  тооцогддог байв. Одоо **өөрийг нь хяналтад авсан эмч** (`PatientMonitoringDoctor`, is_active '1')
  мөн тооцогдоно — `SearchUsers` ба `StartChat` хоёуланд.
- **Шинэ endpoint — эмч асуултад хариулах (2.3):**
  - `GET /api/doctor/monitoring/:patientId/questions?limit&offset` — үйлчлүүлэгчийн
    `GET /api/patient/questions`-тэй яг ижил хэлбэр (`id_data, comment, is_doctor,
    date_creation, doctor_name`), шинэхнээс нь. `Question` моделийг шууд ашиглаж болно.
  - `POST /api/doctor/monitoring/:patientId/questions` `{ "comment": "..." }` → `{ id_data }`.
  - Хяналтад байхгүй үйлчлүүлэгч → `403 NOT_MONITORED`; хоосон хариулт → `400 COMMENT_REQUIRED`.
- Вэб дээр эмч үйлчлүүлэгчтэй чат эхлүүлэх товч нэмэгдсэн (өмнө нь зөвхөн үйлчлүүлэгч эхлүүлж
  чаддаг байв).

## 1. Илгээсэн мессеж бүр хоёр бөмбөлөг болдог (нэг нь "илгээж байна" дээрээ гацдаг)

Сервер `newMessage`-ийг HTTP хариунаас **өмнө** тараадаг бөгөөд илгээгч өөрөө хүлээн авагчдын дунд
байна; payload-д `ClientMsgId` явна.

- `features/chat/chat_controller.dart:229-238` `_onIncoming` зөвхөн `id`-аар давхардлыг шалгадаг.
  Түр бөмбөлгийн `id` нь `0` тул socket-ын хуулбар нэмэгдэнэ.
- `:317-326` `_replaceOptimistic` дараа нь эхний `clientMsgId` тохирохыг — socket-ын хуулбарыг —
  солиод, түр бөмбөлөг цагны тэмдэгтэйгээ үлдэнэ.

**Засвар:** `_onIncoming`-д `message.clientMsgId` тохирох бөмбөлөг байвал түүнийг
`copyWith(sendState: sent)`-ээр соль, эс бөгөөс id-аар шалга. `_replaceOptimistic`-д ижил `id`-тай
мөр аль хэдийн байвал түр бөмбөлгийг хас.

## 2. Токен дуусахад (10 цаг) шууд чат бүрмөсөн зогсдог

- `chat_socket.dart:59` токен socket үүсэх үед нэг удаа л өгөгдөнө; `:45` socket байгаа бол
  `connect()` юу ч хийхгүй; `:137` `reconnectWithFreshToken()` хаана ч дуудагддаггүй.
- Сервер `authExpired` илгээж **тэр даруй** салгадаг (`helper/SocketAuth.js:107-110`), тиймээс
  `:92`/`:111`-ийн `reauth` хаагдаж буй socket руу явна. Серверээс салгасны дараа socket.io өөрөө
  дахин холбогддоггүй; сүлжээ тасарсны дараах оролдлого хуучин токеноор үргэлж татгалзагдана.

**Засвар:** `authExpired`, `io server disconnect`, мөн токен нь дууссан үеийн `connect_error` дээр
socket-ыг устгаж (нэгдсэн өрөөнүүдийг **хадгалж**) `ChatRoomsController.load(refresh: true)`-ийг
дууд — HTTP дуудлага interceptor-оор токеныг сэргээнэ (хуучин давхарга `AuthError: true` буцаадаг),
дараа нь `connect()` шинэ токеноор шинэ socket үүсгэнэ. Давталтаас сэргийлж 30 секундэд нэг удаа.
Холболт сэргэхэд нээлттэй ярианы мессежийг дахин тат.

## 3. Татгалзсан чат чимээгүй алга болдог

`chat_controller.dart:105-107` `startChat` алдааг залгиж `null` буцаана; `chat_rooms_screen.dart:111`
зүгээр л `return`. Серверийн "Зөвхөн өөрийн эмчтэй чатлах боломжтой" гэх мэт мессеж харагддаггүй.

**Засвар:** алдааны мессежийг буцааж SnackBar-аар харуул.

## 4. "Бичиж байна" хэзээ ч харагддаггүй

`chat_socket.dart:125` `{'ChatRoomId': id}` л илгээдэг; сервер `IsTyping: !!data.IsTyping`
(`WebSockets/ChatSocket.js:101`) гэж дамжуулдаг тул үргэлж `false`. Апп `typing` event-ийг сонсдоггүй.

**Засвар:** `IsTyping: true/false` илгээ (2 секундэд нэг удаа, бичихээ болиход `false`), `typing`
event-ийг (`{ChatRoomId, UserId, UserType, IsTyping}`) сонсож гарчгийн доор "бичиж байна…" харуул.

## 5. Хавсралт амжилтгүй болоход

- `chat_repository.dart:147-148` файл оруулалт бүтэлгүйтвэл `CommitMessage` дуудагдахгүй тул
  `'P'` төлөвтэй хоосон мөр илгээгчийн түүхэнд үлдэнэ. Бүтэлгүйтсэн ч `CommitMessage`-ийг дууд —
  файл нэг ч буугаагүй бол сервер мөрийг өөрөө устгана (`ChatController.js:593-597`).
- `chat_room_screen.dart:194-202` дахин оролдоход зөвхөн текст явж, файлууд алга болно. Амжилтгүй
  мессежийн файлуудыг `clientMsgId`-аар хадгалж, дахин оролдоход хамт илгээ.

## 6. Эмчийн модульд асуулт харах дэлгэц байхгүй

Дээрх шинэ endpoint-оор `DoctorMonitoringJournalScreen`-ээс нээгдэх "Асуулт, хариулт" дэлгэц нэм.

## 7. Билд

`pubspec.yaml` нь `path: 1.9.0`, `intl: 0.19.0` гэж бэхэлсэн нь Flutter 3.44-ийн SDK бэхэлгээтэй
(`path 1.9.1`, `intl 0.20.2`) зөрчилдөж `pub get` бүтэлгүйтдэг. Таны локал pubspec засвар үүнийг
шийдсэн байх — push хийгээрэй.
