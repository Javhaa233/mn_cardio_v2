# Зөвлөгөө (Advice) — хавсралт ба дуу бичлэг

**2026-09-15** · Веб талд хийгдсэн. Мобайл талд хийх ажил бий — доороос уншина уу.

Өмнөх баримтууд хэвээрээ: [API.md](API.md) §6 (шинэчлэгдсэн), §4.30,
[CHAT-MEDIA-2026-09-14.md](CHAT-MEDIA-2026-09-14.md) (энэ нь яг ижил механизмыг чатад
ашигладаг).

---

## Юу өөрчлөгдсөн

Эмч зөвлөгөөний тасалбарт **дуу бичлэгээр хариулах** боломжтой болов — чатад байгаатай яг ижил
бичигч. Дуу файл (`.mp3`, `.m4a`, `.wav`, `.ogg`, `.aac`, `.weba`) хавсаргах ч боломжтой.
**Видео ороогүй** — захиалагчийн шийдвэр.

Танд хамааралтай нь **хоёр зүйл**:

| № | Юу | Танд хийх ажил |
|---|---|---|
| 1 | `/api/patient/advice`, `/api/doctor/advice`, `/api/doctor/advice/:id` одоо **`files`** буцаана | Байсан — гэхдээ **өмнө нь огт байгаагүй**. Хавсралт харуулах дэлгэц нэмнэ |
| 2 | `files[].kind` = `audio` бол тоглуулагч харуулна | Дуу бичлэг тоглуулах UI |

Бичих тал (дуу бичиж илгээх) нь **веб дээр л байна**. Мобайл дээрх зөвлөгөөний хэсэг одоогоор
**зөвхөн уншдаг** (`api/doctor/index.js` дээрх тайлбарын дагуу), тиймээс шинэ бичих endpoint
нэмээгүй. Хэрэв мобайл дээр ч эмч дуу бичээд хариулах шаардлагатай бол **хэлээрэй — endpoint
нэмнэ**.

---

## 1. `files` массивын бүтэц

`/api/patient/advice` — тасалбар бүрт **ба** хариулт бүрт.
`/api/doctor/advice` — тасалбарт (жагсаалтад хариулт задлагддаггүй).
`/api/doctor/advice/:id` — тасалбарт **ба** хариулт бүрт.

```json
{
  "id": 91233,
  "name": "voice-20260915T104412.m4a",
  "ext": "m4a",
  "size": 412880,
  "kind": "audio",
  "durationMs": 47120,
  "mediaState": "done",
  "url": "/api/Media/stream/20260915104412_318_1_k3fq"
}
```

### `kind` — өргөтгөлөөс бүү тааварла

`audio` · `video` · `image` · `file`. Серверийн тоглуулах давхарга яг ижил ангилагч ашигладаг
тул хоёр тал зөрөх боломжгүй.

> **`.webm` бол ВИДЕО, `.weba` бол ДУУ.** Хоёулаа яг ижил контейнер — зөвхөн нэрээр нь ялгана.
> Хөтөч дээр бичсэн дуу бичлэг `audio/mp4` дэмжихгүй үед `.weba` болж гардаг (Firefox үргэлж,
> Chrome 130-аас өмнө). `kind` талбарыг уншина уу, өргөтгөлөөр бүү шийд.

### `url` — толгойн баталгаажуулалттай, byte range дэмжинэ

`GET /api/Media/stream/<generated_name>`, `Authorization: Bearer <token>` толгойтой.

- `VideoPlayerController` → `httpHeaders`
- `just_audio` → `AudioSource.uri(..., headers: {...})`

**Blob болгож бүү татаж ав.** 10 минутын дуу бичлэг бүтнээрээ татагдаж дуустал дуу гарахгүй,
дунд нь үсрэх (seek) боломжгүй, санах ойд бүтнээрээ сууна. Энэ нь stream учраас 206 Partial
Content-оор хэсэгчлэн ирнэ.

### `durationMs` — null байж болно

Одоогоор **үйлдвэрлэлийн (production) сервер дээр null** — `add_file_media_columns.sql` тэнд
ажиллаагүй байгаа (захиалагчийн зөвшөөрөл хүлээж байна,
[ZSUT-chat-media-2026-09-14](../ZSUT-chat-media-2026-09-14.md) В.1). Тест сервер дээр байгаа.

null үед **`0:00` бүү бич — зураас (`–:--`) харуул.** Файл ачаалагдсаны дараа тоглуулагч
өөрөө уртыг мэдэж авна.

### `mediaState`

| Утга | Утга учир |
|---|---|
| `pending` | ffmpeg M4A/AAC болгон хөрвүүлж байна |
| `done` | хөрвүүлсэн |
| `failed` | ffmpeg байхгүй сервер — **эх файл хэвээр үйлчилнэ** |
| `null` | багана байхгүй сервер |

`failed` бол алдаа биш. Гэхдээ энэ үед хөтчөөс бичсэн WebM хэвээрээ үлдэх тул **iPhone дээр
тоглохгүй** — [CHAT-MEDIA-2026-09-14.md](CHAT-MEDIA-2026-09-14.md) §6-той ижил шалтгаан.

## 2. Хавсралт татахад `/api/Media/stream` ашиглана

`/api/BaseObject/downloadFile` биш. Хоёр шалтгаан:

1. Энэ нь `GET` бөгөөд byte range дэмждэг — тоглуулагч seek хийж чадна.
   `downloadFile` нь `Content-Disposition: attachment` буцаадаг, үүнийг тоглуулагч уншиж
   чадахгүй.
2. Эрхийг нь мөрөнд нь шалгадаг — Advice болон AdviceComment файлыг
   `AdviceScopeHelper.MayReadAdviceAttachment`-ээр дамжуулна. Өвчтөн зөвхөн өөрийн тасалбарын
   файлыг, эмч зөвхөн харагдах хүрээнийхээ тасалбарыг нээнэ.

`generated_name`-г клиент рүү өгч байгаа нь **задрал биш**: хүсэлт бүр дээр хадгалагдсан мөрийг
дахин баталгаажуулдаг тул нэрийг мэдэх нь юу ч өгөхгүй.

## 3. Танд хэрэггүй зүйл: `GetAttachmentLink`

Веб дээр шинээр `POST /api/Advice/GetAttachmentLink {FileId}` нэмсэн. Энэ нь 1 цагийн хугацаатай,
**нэг файл + нэг хэрэглэгчид** зориулсан түр хаяг буцаадаг
(`/api/Media/t/<ticket>`), учир нь хөтчийн `<audio>` элемент `Authorization` толгой илгээж
чаддаггүй.

**Мобайл дээр хэрэггүй** — та толгой илгээж чадна. Чатад байгаа
`POST /api/Chat/GetAttachmentLink`-тэй яг ижил зарчим.

## 4. Бичих тал — мобайл дээр нэмэх бол

Одоогоор веб дээр л байгаа. Хэрэв хэрэгтэй бол дараах дараалал хэрэгтэй болно (чатынхтай ижил
биш — зөвлөгөөнд commit алхам байхгүй):

```
POST /api/Advice/CreateComment
     { ObjectName: 'AdviceComment',
       Data: JSON.stringify({ adv_com_id_adv: <AdviceId>, adv_com_comment: '<текст>' }) }
  -> { Success, Data: { DataId } }

POST /api/BaseObject/uploadFile        multipart/form-data
     LinkedObjectInfo = {"LinkedObjectName":"AdviceComment",
                         "LinkedObjectId":<DataId>,"FieldName":"Files"}
     File0     = <binary>
     File0Info = {"Name":"voice-....m4a","DurationMs":47120}
```

`DurationMs` заавал биш ч **өгөх нь зүйтэй**: ffmpeg байхгүй сервер дээр урт харуулах цорын ганц
эх сурвалж нь энэ.

Хязгаар: **10 МБ**, зөвшөөрөгдсөн өргөтгөл дээр дурдсанчлан, видео **ороогүй**.

> Анхаар: энэ хоёр алхам **атом биш**. Хоёр дахь нь амжилтгүй бол текст хариулт аль хэдийн
> хадгалагдчихсан байна. Веб тал ч мөн адил. Хэрэв мобайл дээр бичих талыг нэмэх бол үүнийг
> нэг endpoint болгож нэгтгэх нь зүйтэй — **хэлээрэй**.

## 5. Тест хийхэд

Тест сервер: `https://mncardio.itsystem.mn`. `MnCardio_test` дээр `duration_ms` багана байгаа,
ffmpeg суусан — тиймээс `mediaState: "done"` болж, iPhone дээр тоглоно.

Хавсралттай тасалбар олох:

```
GET /api/doctor/advice?filter=all&limit=20
```

`files` хоосон биш мөрийг хар. Одоогоор ихэнх хавсралт **зураг (`kind: "image"`)** — дуу бичлэг
нь энэ өдрөөс хойш бичигдэж эхэлнэ.

> Тест орчны хуучин хавсралтын зарим **байт нь сервер дээр байхгүй** (өгөгдлийн сан сэргээгдсэн
> ч файлууд нь биш). Ийм файл `404` буцаана — энэ нь мэдэгдэж байгаа зүйл, шинэ алдаа биш.
> Зөвлөгөөний файлууд 2026-09-10-нд хуулагдсан тул ихэнх нь ажиллана.

## Асуулт

Хоёр зүйлийг та шийдэх хэрэгтэй, бид хүлээж байна:

1. **Мобайл дээр эмч дуу бичээд хариулах шаардлагатай юу?** Тийм бол §4-ийн хоёр алхмыг нэг
   endpoint болгож нэгтгэе.
2. **Өвчтөн зөвлөгөөнд хавсралт нэмэх шаардлагатай юу?** Одоогоор өвчтөн зөвхөн уншина.
