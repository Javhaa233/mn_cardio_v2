# Чатын дуу, видео мессеж — мобайл хөгжүүлэгчид (2026-09-14)

**Хэнээс:** «АйТи Систем» ХХК — backend
**Хэнд:** мобайл аппын хөгжүүлэгч

Аппликейшний кодыг бид хөндөөгүй. Зөвхөн endpoint.

> **Энэ файл зөвхөн чатын дуу/видео тухай.** Танаас ирсэн 15 зүйлийн жагсаалтын
> хариу — мэдэгдэл, эрх, тохиргоо, export, ЭМД, FHIR гэх мэт — тусдаа файлд байна:
> [HANDOVER-2026-09-14-B.md](HANDOVER-2026-09-14-B.md). Бүрэн лавлах нь
> [API.md](API.md) (§5 чат, §7 файл).

Чат урьд нь дуу файл **зөөж** чаддаг байсан ч, бичих ч, тоглуулах ч боломжгүй
байлаа: хавсралт нь `POST` + `Content-Disposition: attachment`-аар үйлчилдэг
бөгөөд үүнийг ямар ч `<audio>`, `<video>` элемент уншиж чаддаггүй. Одоо
**бичих, илгээх, тоглуулах** гурвуулаа ажиллана.

---

## 1. Тоглуулах — та юу хийх ёстой вэ

**`GetAttachmentLink`-ийг бүү хэрэглээрэй.** Тэр нь `Authorization` header
явуулж чаддаггүй хөтөчийн `<audio>`/`<video>`-д зориулсан. Flutter-ийн
`VideoPlayerController`, `just_audio` хоёр `httpHeaders` дэмждэг тул танд
илүү сайн зам бий:

```
GET /api/Media/stream/<generated_name>
    Authorization: Bearer <token>
    Range: bytes=0-                  # сонголтоор → 206 + Content-Range
```

- жинхэнэ byte-range (`206`, `416`, `HEAD` бүгд дэмжигдэнэ)
- `Content-Disposition: inline` → файл бүрэн ирэхээс өмнө тоглож эхэлнэ, гүйлгэж болно
- `generated_name` нь хавсралтын `FileInfo` дотор

> Энэ route урьд нь чатын файлыг **үйлчилж чаддаггүй** байсан: бичих дүрмээр
> уншилтыг шалгаж байсан тул хүргэгдсэн мессеж бүрийг татгалзаж байв.
> 2026-09-14-нд зассан.

Лавлагаа болгож: `POST /api/Chat/GetAttachmentLink` `{FileId}` →
`{Url, ExpiresAt, Kind, ContentType, DurationMs, MediaState, …}`. `Url` нь
`/api/Media/t/<ticket>` бөгөөд гэрчилгээ нь URL дотроо явна — 1 цаг хүчинтэй,
нэг файл, нэг хэрэглэгчид заагдсан, эргүүлэн шалгагддаг. Хөтөчид л хэрэгтэй.

## 2. Хавсралтын `FileInfo` дээрх 3 шинэ талбар

| Талбар | Утга |
|---|---|
| `Kind` | `audio` · `video` · `image` · `file` — **өргөтгөлөөр биш, үүгээр салгана уу** |
| `DurationMs` | Бичлэгийн урт. Татахаас өмнө `0:42` гэж харуулж болно. Мэдэгдэхгүй бол `null` |
| `MediaState` | `null` · `pending` · `done` · `failed` — **үүнээс болж хавсралтыг нууж болохгүй** |

`Kind`-ийг ашиглах нь чухал: `.webm` нь видео, `.weba` нь дуу — контейнер нь
яг адилхан тул өргөтгөлөөр таах гэж оролдвол дуут мессеж хар дэлгэц болж
харагдана. Сервер аль болохыг нь хэлж өгнө.

---

## 3. Сервер бичлэгийг хөрвүүлдэг — танд нөлөөлөх 4 зүйл

Хөтөч дээр бичсэн дуу WebM/Opus гардаг ба **iPhone тоглуулдаггүй**. Иймд сервер
бичлэг бүрийг **M4A/AAC** (дуу) эсвэл **MP4/H.264+AAC** (видео) болгож
хөрвүүлнэ. Мессеж **хүргэгдсэний дараа** ажилладаг тул илгээхэд саатуулахгүй.

1. хавсралтын **`ext` өөрчлөгдөж болно** — мессежээс дахин уншина уу, бүү кэшлээрэй;
2. **`generated_name` өөрчлөгдөхгүй** — авсан холбоос хүчинтэй хэвээр;
3. `MediaState: 'pending'` → эх бичлэг аль хэдийн тоглогдож байна, зүгээр л жижиг
   тэмдэглэгээ харуулж болно;
4. `MediaState: 'failed'` → эх хэлбэрээрээ үйлчилнэ. **Ямар ч байсан тоглуулна уу** —
   Android дээр ажиллана. (Сервер дээр `ffmpeg` байхгүй бол ингэнэ.)

## 4. Илгээх — өмнөх 3 алхам хэвээр

```
1. POST /api/Chat/SendMessage   { ChatRoomId, MessageText: "", HasAttachment: true, ClientMsgId }
2. POST /api/BaseObject/uploadFile   (multipart, LinkedObjectName: 'ChatMessages',
                                      LinkedObjectId: <MessageId>)
3. POST /api/Chat/CommitMessage { MessageId, ClientMsgId }
```

Дуут мессежид `MessageText` хоосон байж болно.

**`File0Info`-д `DurationMs` явуулна уу.** Бичиж байхдаа та уртыг нь мэдэж
байгаа. Сервер `ffprobe`-оор дахин хэмжиж дарж бичнэ, гэхдээ түүнийг хүртэл —
мөн `ffmpeg` байхгүй хост дээр бол бүрмөсөн — таны өгсөн тоо л харагдана.
Явуулаагүй бол хэрэглэгч `–:--` гэж харна.

### Хязгаар

| | |
|---|---|
| Файлын дээд хэмжээ | **50 МБ — нэмэгдэхгүй** |
| Санал болгох бичлэгийн чанар | дуу 64 kbps; видео 720p, ~1.5 Mbps |
| 3 минутын видео | дээрх чанараар ~35 МБ → багтана |
| Зөвшөөрөгдөх видео | `mp4` `m4v` `mov` `webm` |
| Зөвшөөрөгдөх дуу | `mp3` `m4a` `aac` `ogg` `wav` `weba` |

50 МБ-г нэмэхгүй байгаа нь санаатай: `formidable` нь хязгаараа **аль obj-д
хамаарахыг мэдэхээсээ өмнө** тогтоодог тул өсгөвөл систем дэх бүх upload тэр
хэмжээ хүртэл уншигдаж байж татгалзах болно.

### Агуулгын шалгалт (шинэ)

Дуу, видеоны **эхний байтууд** өргөтгөлтэйгээ таарахгүй бол татгалзана:

```
{"Success":false,"Data":{"Rejected":[{"Name":"x.mp4","Reason":"content",
  "Message":"Файлын агуулга \"mp4\" төрөлтэй тохирохгүй байна"}]}}
```

Зураг, PDF, DICOM, Office файлд энэ шалгалт **хамаарахгүй** — өмнөх шигээ.

## 5. Push мэдэгдэл (чат)

Шинэ мессеж ирэхэд push очдог болов. Урьд нь socket л байсан тул **апп хаалттай
үед юу ч очдоггүй** байлаа.

```
title: <илгээгчийн нэр>
body:  <текст, 120 тэмдэгтээр тайрсан>
       эсвэл  🎤 Дуут мессеж / 🎬 Видео бичлэг / 📷 Зураг / 📎 Файл
data:  { Type: 'chat', ChatRoomId: '<id>', MessageId: '<id>' }
```

- илгээгч рүү болон `IsMuted` тэмдэглэсэн хэрэглэгч рүү **очихгүй**
- апп ажиллах бүрд `POST /api/patient/devices` (эсвэл `/api/doctor/devices`)
  дуудаж төхөөрөмжөө бүртгүүлнэ үү, эс бөгөөс хаашаа ч очихгүй
- push нь **сэрээх дохио**, мессеж өөрөө биш — сэрэхдээ мессежээ дахин уншина уу

---

## 6. Туршиж үзэх

Тест сервер дээр `ffmpeg` суулгасан, `File.duration_ms` / `media_state` багана
нэмсэн, `MEDIA_TICKET_SECRET` тохируулсан.

Санал болгох дараалал:

1. Эмчийн аккаунтаар дуут мессеж илгээх → `Kind`, `DurationMs` зөв ирж байгаа эсэх
2. Үйлчлүүлэгчийн аккаунтаар `/api/Media/stream/<generated_name>`-ээр тоглуулах
3. `Range: bytes=0-1023` явуулж **206** ирж байгаа эсэхийг шалгах (гүйлгэх боломж)
4. Апп хаалттай үед мессеж ирэхэд push очиж байгаа эсэх

Ялгаа гарвал **код нь үнэн** — файл, мөрийн дугаартай нь бичиж явуулаарай, засна.
