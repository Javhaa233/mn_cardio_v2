# МнКардио — Гар утасны апп

Зүрх судасны үндэсний төвийн МнКардио системийн гар утасны хувилбар.

Тендер §33-ын дагуу **нэг апп, хоёр нэвтрэх хэсэгтэй**:

* **Үйлчлүүлэгчийн модуль** — §2.1–2.7
* **Эмчийн модуль** — §1.1–1.5

Нэвтрэх дэлгэц дээр хэсгээ сонгоно. Аль дэлгэц нээгдэхийг **серверийн буцаасан
`RoleId`** тогтооно, сонголт биш: эмчийн хэсгээр орсон үйлчлүүлэгчийн бүртгэл
эмчийн дэлгэц рүү орохгүй.

Апп анхдагчаар **амьд туршилтын сервер** рүү холбогдоно —
`https://mncardio.itsystem.mn`. Локал backend шаардлагагүй; нэвтрэх бүртгэлийг
ITsystem-ээс тусад нь авна ([../QUICKSTART.md](../QUICKSTART.md)).

Эхлэхийн өмнө [SETUP.md](SETUP.md), гэрээний талаар
[../QUICKSTART.md](../QUICKSTART.md), [../API.md](../API.md),
[../READINESS.md](../READINESS.md), [../BLOCKERS.md](../BLOCKERS.md) уншина.

## Гурван зүйл кодыг ойлгоход хамгийн чухал

### 1. Backend-д хоёр өөр дугтуй бий

`/api/patient/*`, `/api/auth/*` нь `{success, message, data, code}` бөгөөд
**жинхэнэ HTTP статус**буцаана. Бусад бүх `/api/*` (чат үүнд багтана) нь
`{Success, Message, Data, Option}` бөгөөд **алдаа гарсан ч HTTP 200** буцаана.

`core/network/envelope_interceptor.dart` хоёуланг нь нэг `ApiException` болгож
хувиргана. Дуудагч тал зөвхөн `ApiException` барина.

Логик заавал `code` дээр салаална, `message` дээр биш — мессеж нь өөрчлөгдөж
болох дэлгэцийн текст.

### 2. Токен сэргээлт нэг л удаа явна

`core/network/auth_interceptor.dart` нь токен хүчингүй болоход **нэг удаа**
сэргээгээд хүсэлтийг давтана. Зэрэг явж буй арван дуудлага арван refresh биш,
нэг refresh өдөөнө. `/api/auth/refresh` өөрөө хэзээ ч давтагдахгүй.

### 3. Монгол хэл бол шаардлага, тохиргоо биш

Хэрэглэгчид харагдах мөр бүр монгол: шошго, товч, алдаа, хоосон дэлгэц,
ачаалалтын текст. Англи локал **байхгүй** бөгөөд нэмэх ёсгүй.

Серверээс ирсэн мессежийг харуулахын өмнө `core/util/mn_text.dart` дахь
`mnMessage()` кирилл эсэхийг шалгана — зарим хуучин хяналт англи текст
буцаадаг.

## Мэдэж байх ёстой хачирхалтай зүйлс

**Доод даралт хадгалагддаггүй.** `GET /journal` нь `blood_pressure2`-ыг
буцаадаг, график зурдаг, гэвч `POST /journal` хүлээж авдаггүй
(READINESS.md §2.9 — нэг мөрийн засвар). Маягт хоёуланг нь илгээдэг; сервер
хадгалаагүй бол хэрэглэгчид шууд хэлнэ, чимээгүй алдахгүй.

**Зөвлөгөөний 57% нь хоосон `body`-той.** Эмнэлзүйн агуулга нь эхний хариунд
байдаг. `Advice.displayBody` үүнийг зохицуулна.

**Цахим үзлэгийн талбар PascalCase.** Дугтуй нь жижиг үсгээр байхад `Id`,
`Comment`, `CreateDate` том үсгээр ирнэ — `RemoteVisit` шинэ үеийн хүснэгт.

**Ард ажиллаж буй апп чатын мессеж хүлээж авахгүй.** Push байхгүй тул socket л
цорын ганц суваг бөгөөд үйлдлийн систем түүнийг таслана. Апп эргэж нээгдэх
бүрд түүхийг дахин татна.

**Хавсралтын жагсаалтад видео өргөтгөл байхгүй.** Сервер зөвшөөрөхгүй.

**Үйлчлүүлэгчийн нэвтрэх нэр кирилл үсгээр эхэлдэг.** Регистрийн дугаар
`ПП83011709` — латин `PP` биш. Хоёр нь нүдэнд ижил, байтаараа өөр. `dio`
UTF-8-ыг зөв илгээдэг тул апп талд асуудалгүй, харин гараар curl эсвэл
PowerShell-ээр туршихад нэр эвдэрч "нууц үг буруу" мэт харагдана.

**Нууц үгийн дүрэм серверийн `helper/PasswordPolicy.js`-тэй яг таарна:**
8+ тэмдэгт, том үсэг, жижиг үсэг, тоо, тусгай тэмдэгт. Үсгийн шалгуур нь
**латин** — серверийн regex ийм тул зөвхөн кирилл нууц үг татгалзана.
Туршилтын сервер хуучин билд дээр байгаа тул өнөөдөр сул нууц үг хүлээж авч
магадгүй; клиент тал дүрмээ баримталсан.

**Сэргээн засах endpoint туршилтын сервер дээр 200 буцаадаг болжээ**
(`add_rehabilitation_tables.sql` ажилласан). Гэхдээ дасгалын каталог **хоосон**
бөгөөд үйлдвэрлэлийн орчинд DDL ажиллаагүй хэвээр. Апп 500-г "модуль
идэвхжээгүй", хоосон жагсаалтыг "дасгал бүртгэгдээгүй" гэж тусад нь харуулна.

**Эмчийн цахим үзлэгийн жагсаалтыг клиент тал давхар шалгадаг.**
`/api/RemoteVisit/GetList` бол ерөнхий CRUD жагсаалт бөгөөд шүүлтгүй дуудвал
**бүх** үйлчлүүлэгчийн хүсэлтийг буцаана. Талбарын нэр өөрчлөгдөж шүүлтүүр
чимээгүй ажиллахаа болих юм бол өөр хүний мэдээлэл карт дээр гарах эрсдэлтэй
тул `DoctorRepository.fetchPatientEvisits` мөр бүрийн `PatientId`-г буцааж
шалгаж, тохирохгүй бол өгөгдөл харуулахын оронд алдаа шиднэ.

**Эмчийн нэвтрэлт хөгжүүлэлтийн орчинд нууц үг шалгадаггүй.**
`NODE_ENV` нь `production` биш үед `UserController.js:246` нууц үгийг огт
шалгалгүй токен өгдөг. Нэвтрэлт ажиллаж байгааг зөвхөн production тохиргоотой
сервер дээр батал.

## Аюулгүй байдлын дүрмүүд

- Токен зөвхөн `flutter_secure_storage` (Keystore/Keychain) дотор.
  `shared_preferences` нь задгай текст.
- Хурууны хээ төхөөрөмжөөс гарахгүй. Серверт биометрийн endpoint байхгүй.
- `POST /api/BaseObject/downloadFile` **хэрэглэхгүй** — эзэмшлийн шалгалтгүй.
  Чатын файлыг `/api/Chat/DownloadAttachment`-аар татна.
- Гарах = хадгалалтыг цэвэрлэх. Сервер токеныг хүчингүй болгодоггүй.
- Нууц утга агуулахад **хэзээ ч** орохгүй. Серверийн хаяг `--dart-define`-ээр.
- Release билд дээр серверийн хаягийг апп дотроос солих боломж хаалттай.

## Туршилт

```bash
flutter analyze
flutter test
```

`flutter analyze` дээр **алдаа (error) болон сануулга (warning) байх ёсгүй**.
`analysis_options.yaml` дээрх дүрмүүд чангалсан (`strict-casts`,
`use_build_context_synchronously` гэх мэт), тул хэв маягийн `info` түвшний
санамж гарч болно — тэдгээрийг `dart fix --apply` -аар цэвэрлэнэ.

> Энэ агуулах Flutter SDK суулгаагүй машин дээр бичигдсэн тул `flutter analyze`
> **хараахан ажиллуулаагүй**. Эхний ажиллуулалт дээр багцын хувилбарын жижиг
> зөрүү гарч болзошгүй — SETUP.md -ийн дагуу тохируулсны дараа эхлээд
> `flutter analyze`, дараа нь `flutter test` ажиллуулна уу.
