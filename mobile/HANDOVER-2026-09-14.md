## The short version

`/api/patient` went from 16 endpoints to **35**, `/api/doctor` from 14 to **26**, plus two new
surfaces: `/api/Media` (video streaming) and `/api/fhir`. Modules **2.6** and **2.7** are
complete, notifications and push exist, and reminders exist.

Your existing calls all still work. Nothing was renamed or removed.

## 1. The bug you reported is fixed, and so is its twin

Saving a note (`POST /api/patient/journal`) and asking a question
(`POST /api/patient/questions`) both returned 500. Fixed and deployed on 2026-09-11 — you may

not record the bottom number. Send both halves.

## 2. Module 2.6 Цахим үзлэг — now the whole flow

Was a complaint box. Now request → appointment → examination.

```
GET  /api/patient/evisits            ?limit &offset &status &from &to
POST /api/patient/evisits            { "Comment": "..."*, "RequestedDate": "..." }
GET  /api/patient/evisits/:id
POST /api/patient/evisits/:id/cancel { "Reason": "..." }
```

`requested → scheduled → completed`, with `cancelled` reachable from either open state.
`completed` and `cancelled` are **terminal for everyone** — a repeat consultation is a new
request, not a reopened one. An illegal move answers `409 INVALID_TRANSITION`.

> **`MeetingUrl` is only present while `Status === 'scheduled'`.** It is null before and after,
> deliberately — a join link is a credential for a clinical conversation, so it is not handed
> out while a request is pending nor left live once the visit is over. Do not cache it.

`RequestedDate` is **optional**: `{ Comment }` alone still works, which is what your current
code sends. A past date gives `400 DATE_IN_PAST`.

A patient may hold **3 open requests**; a fourth gives `409 TOO_MANY_OPEN_REQUESTS`.

Field names are PascalCase *inside* the lowercase envelope — `RemoteVisit` is a
newer-generation table. Do not assume the envelope's casing reaches the fields.

**Doctor side** (§2.6b in API.md): `GET /api/doctor/evisits?scope=mine|unassigned|all`, plus
`/schedule`, `/complete`, `/cancel`. `scope=unassigned` is care-team scoped.

## 3. Module 2.7 Сэргээн засах — the catalogue has rows now

`GET /api/patient/rehab/exercises` returned `[]` forever. It now returns **39 rows**.

> **They are PLACEHOLDERS and every row says so in Mongolian** — *"Дасгал №1 — нэр
> батлагдаагүй"*. The real names, categories and durations are clinical content ЗСҮТ own, and
> filming has not started. They exist so you have real ids, real ordering, real categories to
> group by, and a real "no video" state to build against. **Do not ship a screenshot of them.**

Each row now carries `CategoryLabel` and a parsed `media` object.

### The one contract to get right: never parse `MediaRef`

Branch on `media.kind`. Treat `media.url === null` as "no video yet", not as an error.

| `media.kind` | meaning | what to do |
|---|---|---|
| `null` | not filmed yet — **every row today** | show the exercise, no player |
| `"file"` | on the MnCardio server | play `media.url` |
| `"url"` | cloud / CDN | play `media.url` |
| `"asset"` | bundled in the app | play your local asset named `media.ref` |

Where the 39 videos will live is still an open customer question. This is what stops that
answer costing you an app release — it becomes a database value.

**New doctor endpoints:** `GET /api/doctor/rehab/exercises`,
`GET /api/doctor/patients/:id/rehab`, and `GET`/`POST /patients/:id/rehab/assessment`. That
last one closes a real gap: the patient's assessment screen read a row that nothing could ever
write, so it was permanently empty.

## 4. Video playback — `/api/Media/*`

```
GET  /api/Media/exercise/:exerciseId
HEAD /api/Media/exercise/:exerciseId
GET  /api/Media/stream/:generatedName
```

Real HTTP byte ranges: `200` with `Accept-Ranges` and `Content-Disposition: inline`, `206`
with `Content-Range` for a range, `416` for an unsatisfiable one. Suffix ranges work. So the
player can seek.

> **Use `media.url` from the catalogue — don't build this path yourself.**

> **Send the token as a header.** `VideoPlayerController.networkUrl(..., httpHeaders: {...})`
> takes one. Please don't ask for a `?token=` variant: a token in a URL ends up in nginx access
> logs and anywhere the URL gets copied.

## 5. Notifications — patients could not read a single one before

```
GET  /api/patient/notifications              ?limit &offset &unread=1
GET  /api/patient/notifications/unread-count
POST /api/patient/notifications/:id/read
POST /api/patient/notifications/read-all
```

- **`NotesMn` is what you display.** `Notes` is an English developer label — not for users.
- `Seen` is a **boolean** here, even though the column underneath is a string.
- `LinkObjectName` + `LinkObjectId` are the deep link: `VisitComments` → questions thread,
  `RemoteVisit` → the e-visit, `Advice` → the advice item.
- Branch on `Action`, and fall back to showing `NotesMn` for anything you don't recognise —
  more producers will be added.

Wired today: a doctor answering a question (`ReplyQuestion`), and a slot being confirmed
(`EvisitScheduled`). That second one is why you no longer need to poll for appointments.

## 6. Push — build it now, it works without credentials

```
POST /api/patient/devices             { token*, platform*, device_id, app_version, locale }
POST /api/patient/devices/unregister  { token* }
GET  /api/patient/devices
```

The doctor app has the identical three under `/api/doctor/devices`.

> **This works today with no Firebase project and no Apple key.** The server runs a log driver
> that records what it would have sent and reports success — so build and test your whole
> registration and logout flow now. **Nothing in your client changes when ЗСҮТ supply the
> credentials**; a device simply starts buzzing.

- **Register on every launch**, not only first install — FCM and APNs both rotate tokens.
  Re-sending a known token is an upsert, and if it's registered to a different account it is
  **moved** to yours. That's what stops a shared device delivering someone else's clinical
  notifications to you.
- **Unregister on logout**, passing the token.
- It's `POST .../unregister`, not `DELETE /devices/:token`, because an FCM token is ~163
  characters and contains `:` and `-`.
- `GET /devices` never returns the token itself.

## 7. Reminders — medication, exercise, follow-up

```
GET    /api/patient/reminders          ?type &include_inactive=1
POST   /api/patient/reminders          { title*, times_of_day*, reminder_type, frequency, ... }
PATCH  /api/patient/reminders/:id
DELETE /api/patient/reminders/:id      soft — stops firing, keeps history
```

> **`times_of_day` must be zero-padded `HH:mm`.** `"8:00"` is rejected with `400 INVALID_TIME`
> on purpose: the dispatcher compares it as a string against the current local minute, so
> `"8:00"` would never match `"08:00"` and the reminder would **silently never fire**.

> **Times are LOCAL wall-clock.** `"08:00"` means eight in the morning where the patient is.
> Do **not** send UTC or an offset — the server runs UTC and converts to Asia/Ulaanbaatar
> itself. (Getting this wrong would have fired every morning reminder eight hours late.)

`days_of_week` is `1`–`7`, **1 = Monday**; `null` means every day. Delivery is **exactly once
per occurrence**, even across a server restart, so you never need to de-duplicate client-side.

## 8. Option lists — please don't hardcode the Mongolian

```
GET /api/patient/options/:dico
```

Allowlisted: `remotevisit_status`, `rehab_category`, `rehab_risk`, `rehab_phase`,
`patient_reminder_type`, `patient_reminder_freq`, `consent_purpose`.

**All of this wording is drafted by ITsystem and not yet approved by ЗСҮТ.** It will change.
Read it from here and approval costs a database row instead of an app release. An empty array
means the dictionary isn't seeded on that server — show "not configured", not an error.

## 9. Session handling changed

```
POST /api/auth/logout        ends this session
GET  /api/auth/sessions      where am I signed in
POST /api/auth/logout-all    the "I lost my phone" button
```

Logout now genuinely invalidates the token — it previously returned success and left the token
valid for its full ten hours. **Call `/api/auth/logout` on sign-out** and drop your local copy.

Also new: `GET /api/patient/access-log` (who opened my record), and
`/api/patient/consents` (grant/withdraw consent for non-treatment use).

## 10. Corrections to things API.md previously told you

Two of these were my errors and I'm sorry for any time they cost:

- **`/api/BaseObject/downloadFile` was described as having no ownership check.** It does, and
  has for a while — it 403s. You do not need to route around it.
- **`/api/doctor/devices` was documented before it existed.** It exists now.
- `/api/base/*` and `/api/report/*` used to answer without a token. They return **401** now, so
  if you were relying on that, you need a token.
- Four `/api/Test/*` routes were deleted, including `PUT /api/Test/uploadFile`.
